## Clone a set list

Every set list on the start screen now has a **clone** button. Name the copy
and it opens on the song list, which is where you go to change which songs are
in it.

A second set is usually a first set with a few songs swapped. Rebuilding that
by re-adding and re-aligning forty stems is the work this removes.

Stems are hard-linked rather than copied where the filesystem allows it, which
it does for two folders side by side in Documents — so a clone is instant and
costs no disk, whether the set is 8 MB or 8 GB. Nothing ever writes to a stem,
since alignment lives in the set list file, so the sharing cannot be observed.
Copying is the fallback when linking is not possible, which is across drives.

## Tuning in the edit set list

A column between tempo and tracks. That screen is where a set gets ordered,
and grouping songs that share a tuning is most of what ordering a set is for.

## The song editor stops rounding the tempo

It showed two decimal places, so a backing track at 96.515 BPM read as 96.52 —
a different song by a third of a beat by beat 1000, and a screen disagreeing
with its own file. It now shows the shortest text that parses back to exactly
what is stored, which is the rule the file itself uses.

**That rule turned up a real defect.** Writing a set list reached for a format
that renders a tempo of 120 as `1.2e+02`. Valid JSON, and no use at all in a
file whose point is being readable and editable by hand. Existing set lists
written by the program may contain tempos in that form; they load correctly,
and re-saving one now writes it plainly.
