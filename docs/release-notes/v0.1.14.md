Jumping backwards through a set works.

## The bug

The preload window holds the current song and the next one, so a song played
earlier is freed to keep memory bounded — which is exactly what happens when
you jump around a set in rehearsal. Coming back to it, play did nothing.

v0.1.13 noticed the song was not in memory and waited for it to arrive. What
it never did was *ask* for it: the only thing that moves the loader's window
is the call that path exists to avoid. So it waited for something that was
never going to happen, silently.

## The fix

Pressing play on a song that is not loaded now asks the loader for it and
starts the moment it arrives, with a band across the screen naming the song
while you wait.

**Browsing the set list also warms the loader.** Moving the selection with the
arrows or the mouse starts fetching that song before anything is pressed, so
picking a song to work on usually finds it already in memory by the time you
hit SPACE. Only while stopped — while playing, the window belongs to the
transport.

## Notes

The test for this initially passed against a deliberately broken
implementation, because it checked arrival with a call that requests the load
as a side effect. It polls residency directly now.
