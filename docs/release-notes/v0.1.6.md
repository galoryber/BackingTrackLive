The version where nothing needs a terminal.

Every earlier release assumed you would open a command prompt at some point:
to point `btui` at a set list, to find out what your audio interface is
called, to hand-write `device.json`, or to check a set before a gig. All of
that is now in the UI.

## Open the program and use it

Launching `btui.exe` with no arguments used to open an unsaveable demo. It now
reopens your last set list, or offers a start screen: **open a set list**,
**new set list**, **create a demo set**, and anything you have opened before.
Arguments still work and still win.

A new set list is a folder with one song and a click in it, opened straight in
the editor. Stems dragged in from anywhere are copied into the folder — the
folder has to stay self-contained to be copyable to the backup laptop, and
that is not a chore you should have to know about.

## Configure audio on screen

**Edit → audio** lists every device with its API, channel count and latency,
and maps buses to channels with toggles rather than typed numbers. Picking a
four-output interface defaults front of house to the first pair and the click
to the second. Saving reopens the stream, so a routing change does not need a
restart.

Defaults are now the ones measured on a real stage laptop: **512 frames, 48
kHz, WASAPI**. The previous default came from PortAudio and was MME, at
roughly four times the latency.

MME and DirectSound are behind a checkbox. They work, and offering them beside
WASAPI as equals invites the wrong choice.

## Check and export on screen

**Edit → check** is `btcheck` in a screen: every problem in the set at once,
errors first, and clicking one jumps to the song or track it is about. The
same screen renders a song or the whole set to a WAV.

## Where things live

One rule: **machine config is invisible, your content is visible.**

- Settings and routing: `%APPDATA%\BackingTrackLive\`
- Set lists and stems: `Documents\BackingTrackLive\` by default

Routing describes your interface, not any one set list, so it is configured
once and applies to every set you open. An upgrade replaces the program and
touches neither — there is nothing to set up again afterwards, and no import
step. A `device.json` inside a set list folder still overrides the machine's,
which is both how every earlier version worked and how you would pin one set
to unusual routing.

Set lists do not have to live in Documents; it is only where the pickers
start. A set list folder is self-contained, so keeping the band's on a USB
stick works, and the backup laptop then needs nothing but its own routing.

## Also

- The device badge is smaller, and carries a running xrun count, so "nothing
  went wrong" and "nothing is being counted" stop looking identical.
- `--make-demo` moved into the library so the UI and the CLI write the same
  demo, and it gained a test that checks the demo is a valid set list — it is
  also the worked example people copy.
- Coverage floors raised to 95% line and 72% branch.

## Still not here

- **Stem alignment against a waveform.** The nudge is numeric. `bt_peaks` is
  built and tested; the view is not.
- **Tempo maps and track reordering** are supported by the file format and not
  yet by the editor.
- **ASIO.** These binaries are WASAPI-only; the Steinberg SDK cannot live in
  the repository. On a four-output interface WASAPI gives you four channels
  and about 22 ms, which is what the measurements in `docs/gig-laptop.md` were
  taken with.
- **No MIDI and no footswitch.**
