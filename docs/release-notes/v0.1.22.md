A cloned set list now carries the name you cloned it as.

## The fix

Cloning copied `setlist.json` byte for byte, name field and all — so a set
list in a folder called *ClonedSetListTest* still announced itself as the set
it came from, on the set list screen and everywhere else the name is read.
Only the folder was right.

The copy is loaded and re-saved with its new name now, through the model
rather than by editing the text, so what lands is exactly what the program
would have written. A set list cloned from one written by an older version
also gets its tempos rewritten plainly on the way through.
