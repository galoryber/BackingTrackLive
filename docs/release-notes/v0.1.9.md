The waveform. Plus two fixes you should not have had to work around.

## See where a stem actually sits

**Edit → a song → a stem → align.** The stem is drawn where it will *sound* —
its nudge included, not where the file says — against the click grid, which is
computed from the beat index exactly as the click is. What you see is where
the click will land.

The usual fault in a purchased backing track is lead-in silence: the music
starts some way into the file, and how far is whatever the vendor's exporter
happened to do. The view reports it as a number — *"its first sound lands 380
ms after beat 1"* — and **snap start to beat 1** does the arithmetic for you.
Check it by ear afterwards; the snap finds where the audio crosses a
threshold, which is exactly right for a track that starts on a hit and worth
a second look on one that fades in.

Drag the waveform to nudge, scroll to zoom, and it follows the playhead while
playing. Amber marks the stem's first and last sample, bright lines are bar
starts.

A stem has to be loaded to be drawn, because only the loader thread owns stem
memory. Opening align on a song that is not current offers to load it.

**If the fix holds, it was lead-in silence.** If the stem drifts instead —
tight at the top, loose by the last chorus — the tempo is wrong rather than
the offset, and no nudge will fix it. That is a tempo map, which the file
format supports and the editor does not expose yet.

## Two fixes

**Stop in the song editor did nothing.** It shared a label, and therefore an
identity, with the on_end "stop" radio button beside it, so ImGui could not
tell which one a click meant. The only warning appeared on hover.

**Opening another set list crashed.** Closing the set nulls it, and a bounds
check three lines later still used it.

## And why neither was caught

ImGui detects conflicting widget IDs only while the offending item is hovered,
so a headless render never sees one and neither does a screenshot — which is
how it reached v0.1.8. `tools/lint-imgui-ids.py` now checks for it statically
and runs in CI, verified by reintroducing the bug and watching it name both
lines. CI also renders the align and check screens now, rather than three.
