A stem added to a new song is now loaded, so you can align it without
restarting.

## What was wrong

A song with nothing to load counts as in-memory from the moment the program
starts — which is what a brand new song, holding only a click, is. Add a stem
to it and the loader had no reason to believe anything had changed, so the
audio was never fetched. The align view reported that the song was not loaded,
and the button offering to load it failed with the memorable message *"could
not load: ok"*.

Closing and reopening the program fixed it, because the set list it read on
the way back in already had the stem in it.

That message was a second bug: it reported the loader's last error, which was
*ok* because the loader had never been asked to do anything. It now says what
actually failed, and says plainly when a song's stems are simply not in memory
yet.

## Notes

ThreadSanitizer caught the first version of the test for this reading a
track's audio pointer from the wrong thread — the one thing this project's
rules forbid outright. Chasing that turned up a real flaw in the fix as well:
marking a song as changed left it reported as still loaded until the loader
got round to it, so anything asking got a stale yes.

## Still not here
