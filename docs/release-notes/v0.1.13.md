The tuning field v0.1.12 forgot, and the screen stays put between songs.

## Tuning, this time with somewhere to type it

v0.1.12 stored a tuning note, saved it, and showed it on the set list, beside
the artist while playing, and in the NEXT panel — and had nowhere to enter
one. The field is now where it should have been all along, beside the title
and artist in edit mode.

Free text, shown exactly as typed. `E1`, `D1`, `capo 3` — whatever shorthand
the band already uses. Blank shows nothing.

## A song that ends holds the screen

Finishing a song used to drop back to the set list. That is tidy, and it is
not what the moment is: the band has just finished, somebody is talking to the
room, and what matters is that the next song is queued and one key starts it.

The playing screen now stays, showing **UP NEXT** — title, artist, tuning,
tempo. **SPACE** starts it. **↑ ↓** queue a different song without leaving.
**L** opens the set list when you want to see the whole thing.

A segue is unchanged; it never left the screen in the first place.

## Pressing play on a song that is not loaded yet

`bt_player_select` waits for the loader on the calling thread. For a stem
added moments ago, nothing has decoded it yet, so the window froze — no
redraw, no response, and from the outside a key that did nothing, until the
wait finished and it worked. Doing something else first gave the loader time,
which is what made it look intermittent.

The UI now asks whether the song is resident, says **loading …** when it is
not, and starts it the moment it is. Waiting is right for the engine and wrong
for a window.
