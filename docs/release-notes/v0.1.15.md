**A new set list could destroy an existing one. Update before building a set
you care about.**

## The bug

Creating a set list opened `setlist.json` for writing, which truncates
whatever is already there — and the folder picker opened *on* the set lists
folder itself. So making a second set list, without first navigating
somewhere, overwrote the first one. Silently, with nothing to undo it.

Stems were not touched: nothing deleted the audio files, only the set list
that referenced them. If this happened to you, look in your set list folder
before redoing the work — the files are probably still sitting there.

## The fix

A new set list is **named before anything is written**, and gets a folder of
its own. There is no directory picker in that path any more: offering one is
what let someone land on an occupied folder. Creating one also refuses
outright if a set list is already there.

## The start screen lists your set lists

Which it should have done from the beginning. "Open one of mine" was the
common case and the only thing the screen did not offer, leaving a file dialog
and a recents list to carry it.

## Smaller things

- **Adding a song opens it.** Adding one and then finding and pressing *edit
  song* was two actions for one intention.
- **Saving a song returns to the set list**, so finishing a song is one press
  rather than two — and the second press sat next to *leave edit mode*.
- **New songs count in for two bars.** One is barely enough to find the tempo.

## Still not here

- **Tempo maps**, for a song whose tempo changes partway through.
- **Spoken count-in cues** — mostly supported already; see
  [docs/roadmap.md](../roadmap.md).
- **ASIO**, and **MIDI**.
