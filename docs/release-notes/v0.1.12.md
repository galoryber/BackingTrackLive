Track reordering.

## Move a track within a song

**move up** and **move down** beside *+ add stem*, acting on the selected
track. Order has no effect on what is heard — the mixer sums the tracks and
addition does not care — so this is about how a song reads to the person
editing it, which is reason enough: a forty-song set is easier to work on when
the click is where you expect it and the stems are in the order you think
about them.

Because order changes nothing audible, **reordering makes no sound at all**,
even mid-playback. It updates the editor's view without asking the engine to
rebuild. A nudge still costs a brief blip, because a nudge is doing real work.

Removing a track now also leaves the selection somewhere sensible instead of
pointing at whatever moved into that slot.

## Tuning

A song can carry a tuning note — **`E1`**, **`D1`**, whatever shorthand the
band uses — entered beside the title in edit mode and shown on stage in three
places: on the set list beside the tempo, beside the artist while the song
plays, and in the **NEXT** panel, which is the moment you would reach for a
different guitar.

Free text, displayed verbatim. Baking one band's shorthand into the file
format would be wrong for the next band, and wrong for this one as soon as the
shorthand changes.

## Notes

`bt_song_move_track` lives in the model rather than the editor, because the
part worth getting right is that a track carries everything with it —
including the loader's audio pointer, where a mismatch would play the wrong
stem or free something twice.

## Still not here

format supports them and the engine plays them correctly; what is missing is a
way to edit one. `docs/roadmap.md` records what it would take. Not urgent by
agreement — the set has no such song yet.
