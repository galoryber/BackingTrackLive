Packaging fix, again. [v0.1.1](https://github.com/galoryber/BackingTrackLive/releases/tag/v0.1.1)
contained all four tools and also thirteen test executables, because the fix
for v0.1.0 replaced a hand-written filename with a glob — and the release job
builds the tests in order to run them. Same code; the Windows archive is now
about 600 KB rather than 2.7 MB.

Both failures came from the same place: a list of what to package that could
drift away from what was built. The verify step now fails the job in **both**
directions — a missing tool, or anything in the package nobody asked for.

## What is in the archive

| | |
|---|---|
| `btui` | the stage UI — play mode and the set list / song editors (Windows) |
| `btplay` | plays a set list through a real audio device |
| `btrender` | renders a set list offline to WAV |
| `btcheck` | finds everything wrong with a set list in one pass |
| `docs/` | including `gig-laptop.md`, the runbook for the machine that plays the show |
| `examples/setlist/` | a runnable example |

## Everything else

Unchanged since v0.1.0, including what does not work: no ASIO in these
binaries, dropout behaviour on real hardware unmeasured, hot-unplug
unverified, no waveform alignment, no footswitch, and the macOS and Linux
builds have never been run by anyone.
