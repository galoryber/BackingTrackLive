First tagged build. Useful, and not finished — this is a working engine with
a stage UI, not a product you should trust a paying gig to yet.

## What works

**The engine.** Multi-track playback with a generated click, per-stem gain and
millisecond nudge, routing to logical buses, count-in, and song-to-song segue.
Beat positions are computed from the beat index rather than accumulated, so a
three-hour set does not drift — there is a test that places a click at beat
889,000 and checks it lands on the exact sample.

**Stems in the formats you actually buy.** WAV, FLAC and MP3, detected by
content rather than by extension, resampled to the device rate once at load.
The resampler's response is measured, not asserted: flat to 0.000 dB through
19 kHz for 44.1→48.

**A set list that is a text file.** `setlist.json` is hand-editable, diffable
and portable — stem paths are relative, so the folder copies to a backup
laptop as one unit. Saving is lossless and byte-stable, so re-saving an
unchanged set list produces no diff.

**Four tools.** `btplay` plays through a real device; `btrender` renders a set
list offline to WAV; `btcheck` finds everything wrong with a set list in one
pass, before soundcheck rather than during it; `btui` is the stage UI.

**A stage UI.** Play mode switches itself: the set list when stopped, bar
number and what-is-next when playing. Edit mode (`E`, blocked while playing)
has set list and song editors.

## What does not work yet

- **ASIO.** These binaries are WASAPI-only, because the Steinberg SDK cannot
  live in the repository. On a four-output interface such as the UMC404HD that
  matters: Windows shows it to WASAPI as two separate stereo endpoints, so
  separate click routing needs ASIO. The stereo fallback — band mix one side,
  click the other — works today. See `docs/asio.md`.
- **Dropout behaviour on real hardware** is unmeasured, and **device hot-unplug
  is unverified** — written against what PortAudio documents, never watched
  happening. See `docs/gig-laptop.md`.
- **Stem alignment against a waveform** is not built. The nudge is numeric; the
  envelope code behind the waveform view is in place and tested.
- **No MIDI and no footswitch**, so it cannot yet be driven hands-free.
- **macOS and Linux build and pass their tests**, but nobody has run them.

## Notes

Windows binaries link the C runtime statically — unzip and run, no
redistributable. Nothing but CI needs a compiler, including the machine that
plays the show.

Tested on every push across Linux, macOS and two Windows images, under
AddressSanitizer, UndefinedBehaviorSanitizer and ThreadSanitizer, with fuzzing
over every parser and an allocation-failure sweep that requires no error path
to leak.
