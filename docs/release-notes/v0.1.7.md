Fixes from the first session with someone who had not seen the software
before. Several of these are things that should never have shipped.

## You can click on things

Play mode was keyboard-first, which is right for a stage, and it meant the set
list looked like a list of buttons and behaved like a wall: **clicking a song
did nothing at all**. One click now chooses and a double-click plays, which is
what a list of songs does everywhere else, and which keeps an accidental
single click harmless.

**Pressing play on a song that would not load also did nothing, silently** —
indistinguishable from a dead keyboard. The player always knew which song and
why; the UI discarded it. It now says so on screen, including the one failure
that produces silence rather than an error: a track routed to a channel the
open device does not have.

## Songs that are only a click

A song's length was the end of its longest stem, so a song with no stems —
the band plays, only the drummer needs the click — counted in and stopped on
the same frame.

Songs now have a **length in bars**, in the song editor, which shows you the
resulting time as you type. Zero still means "as long as the stems" and is not
written to the file. A length longer than the stems extends the click past
them, for an outro the backing track does not cover.

## Opening a different set list

Click the set list's name, or press **O**. Both blocked while playing, like
edit mode. Launching still reopens your last set list rather than showing a
menu, because on a gig laptop you want to boot into the show.

## It is obvious what to run

The UI executable is now **`BackingTrackLive.exe`**, with an icon and a
version block, so an unzipped release has one obvious thing in it and Explorer
shows a real name. The README says which of the four to run, and that the
other three exist for scripting.

The title bar used to read **"B"**. The window class is registered Unicode but
the window procedure called the generic `DefWindowProc`, which without
`UNICODE` defined is the ANSI one; a Unicode `WM_SETTEXT` read as ANSI stops
at the first zero byte. `PeekMessage` and `DispatchMessage` had the same
mismatch.

## The checker cries wolf less

A stem that needs converting to the device rate is now a **note**, not a
warning, and does not count against the set. It is true, it costs a little
load time and memory, and it costs nothing anyone can hear. Filing that beside
"this stem is silent" is how a checker teaches people to scroll past warnings.

The export section now leads with "optional — you do not need this to play a
show", and says what it is actually for.

## Still not here

Unchanged from v0.1.6: no waveform alignment view, no tempo maps or track
reordering in the editor, no ASIO, no MIDI.
