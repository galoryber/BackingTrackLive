One fix, from two reports that turned out to be the same fault.

## The audio interface is on screen

There was no indication anywhere that an interface was present, and unplugging
one mid-song stopped the music without saying why. Both had the same cause:
the device name and the disconnection message went to the **window title**,
which is invisible in fullscreen and easy to miss anywhere else. The detection
was working — the transport stopped and the set list came back — it just
explained itself where nobody would look.

The set list footer now carries a dot and the device name: **green** with the
interface and API when a stream is open, **red** with the reason when not.
"Am I plugged in and ready" is the question asked before counting a song in,
and it now has an answer on the screen already being looked at.

While playing, a working device says nothing — it is audible. An absent one
says so.

## Also

`btui --shot` gains a `disconnected` state, so the failure screen can be
reviewed like every other one. It was the only screen with no picture, which
is a poor property for the screen that appears when something has gone wrong.

## Still not done

Dropout behaviour across buffer sizes is still unmeasured — that is the next
thing, and the last one standing between "it plays" and "I would trust it at a
gig". No waveform alignment, no MIDI or footswitch, no routing editor in the
UI. macOS and Linux build and pass their tests, and nobody has run them.
